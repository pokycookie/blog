# 신입 개발자 1년, 배운 것들

첫 직장에서 1년을 보내며 배우고 느낀 점들을 공유합니다.

## 입사 전 vs 입사 후

### 입사 전 생각

- "코드만 잘 짜면 되겠지"
- "학교에서 배운 걸 써먹으면 되겠지"
- "혼자 개발하는 거랑 비슷하겠지"

### 입사 후 현실

- 코드보다 커뮤니케이션이 더 중요
- 실무는 학교와 완전히 다름
- 협업이 핵심

## 기술적으로 배운 것들

### 1. 코드 리뷰의 중요성

처음엔 코드 리뷰가 부담스러웠습니다.

```javascript
// 내가 짠 코드
function getUserData(id) {
  const user = users.find(u => u.id === id)
  return user
}

// 시니어의 피드백
function getUserById(id) {
  // Early return으로 가독성 개선
  if (!id) return null
  
  const user = users.find(u => u.id === id)
  
  // 명확한 에러 처리
  if (!user) {
    throw new Error(`User not found: ${id}`)
  }
  
  return user
}
```

**배운 점:**
- 함수명은 명확하게
- 에러 처리는 필수
- Early return으로 가독성 향상

### 2. 테스트 코드

학교에선 안 배웠지만 실무에선 필수입니다.

```javascript
// 처음엔 이렇게만
function add(a, b) {
  return a + b
}

// 이제는 테스트도 함께
describe('add', () => {
  it('두 숫자를 더한다', () => {
    expect(add(1, 2)).toBe(3)
  })
  
  it('음수도 처리한다', () => {
    expect(add(-1, 1)).toBe(0)
  })
  
  it('소수점도 처리한다', () => {
    expect(add(0.1, 0.2)).toBeCloseTo(0.3)
  })
})
```

**배운 점:**
- 테스트는 문서화의 역할도 함
- 리팩토링 시 안전망
- 버그를 미리 발견

### 3. Git 제대로 쓰기

```bash
# 처음엔
git add .
git commit -m "수정"
git push

# 이제는
git add -p  # 변경사항 확인하며 추가
git commit -m "feat: 사용자 검색 기능 추가

- 검색 API 엔드포인트 구현
- 검색 결과 페이지네이션 추가
- 검색어 하이라이팅 기능

Closes #123"

git push origin feature/user-search
```

**배운 점:**
- 커밋 메시지는 명확하게
- 작은 단위로 자주 커밋
- 브랜치 전략 이해

### 4. 레거시 코드 다루기

```javascript
// 레거시 코드 (5년 전)
var data = []
function getData() {
  $.ajax({
    url: '/api/data',
    success: function(res) {
      data = res
      updateUI()
    }
  })
}

// 리팩토링 (점진적으로)
async function fetchData() {
  try {
    const response = await fetch('/api/data')
    const data = await response.json()
    return data
  } catch (error) {
    console.error('Failed to fetch data:', error)
    throw error
  }
}
```

**배운 점:**
- 한 번에 다 바꾸려 하지 말기
- 기존 코드에도 이유가 있음
- 테스트 먼저 작성

## 비기술적으로 배운 것들

### 1. 커뮤니케이션

**질문하는 법**

```
❌ 나쁜 예:
"이거 안 되는데요?"

✅ 좋은 예:
"로그인 API 호출 시 401 에러가 발생합니다.
- 환경: 개발 서버
- 재현 방법: [...]
- 시도한 것: [...]
- 에러 로그: [...]
도움 부탁드립니다."
```

**보고하는 법**

```
✅ 좋은 보고:
"[진행 상황]
- 완료: 사용자 검색 API (80%)
- 진행 중: 검색 결과 UI (50%)
- 예정: 페이지네이션 (0%)

[이슈]
- 검색 속도 최적화 필요 (현재 3초)
- 해결 방안: 인덱스 추가 예정

[일정]
- 예상 완료: 금요일"
```

- 버퍼 시간 포함

## 실수와 교훈

### 실수 1: 프로덕션 DB 삭제

```sql
-- 개발 DB에서 하려던 쿼리를
-- 프로덕션 DB에서 실행...
DELETE FROM users WHERE ...
```

**교훈:**
- 환경 확인은 필수
- 위험한 쿼리는 트랜잭션으로
- 백업 확인

### 실수 2: 하드코딩

```javascript
// 급하게 짠 코드
if (userId === 123) {
  // 특정 사용자만 처리
}
```

**교훈:**
- 임시 코드는 영구적이 됨
- 설정 파일로 관리
- TODO 주석 남기기

### 실수 3: 과도한 최적화

```javascript
// 불필요한 최적화
const memoizedValue = useMemo(() => {
  return value + 1  // 간단한 연산
}, [value])
```

**교훈:**
- 측정 없는 최적화는 악
- 병목 지점부터 개선
- 가독성이 우선
